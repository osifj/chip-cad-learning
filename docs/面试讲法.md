# 面试讲法

这份文档帮你把项目讲得真实、有分寸、有技术含量。不要把自己包装成“精通 IC 设计”。你要表达的是：我正在系统学习，并且已经能跑通、理解、修改基础自动化脚本。

## 1. 一句话介绍

中文：

> 这是一个面向 EDA / IC CAD 实习的零基础训练项目，我用 Shell、Tcl、Python 和 Makefile 做了环境检查、EDA log 解析、testchip 数据分析、reference flow 自动化和统一 CLI 工具箱。

英文：

> This is a beginner-friendly EDA / IC CAD automation training project where I practiced Shell, Tcl, Python and Makefile through environment setup, EDA log parsing, testchip data analysis, reference flow automation and a unified CLI toolbox.

## 2. 中文 1 分钟介绍

> 我做了一个面向 EDA / IC CAD 实习的自动化学习项目。项目不是商业软件，而是把实习岗位里常见的脚本任务拆成 5 个小模块。Week 1 用 Shell 做环境检查和 EDA 环境变量配置；Week 2 用 Tcl 解析 DC/PT 风格 log，提取 area、power、cell count、worst slack 和 warning；Week 3 用 Python/pandas 分析 testchip CSV，生成良率和参数统计报告；Week 4 用 Makefile 模拟 synth、place、CTS、route、STA、PV 的 reference flow，并用 `.done` 文件做断点续跑；Week 5 把前面功能封装成 `chipcad` 命令行工具。通过这个项目，我重点训练了 Linux、Shell、Tcl、Python 数据分析和 EDA flow 自动化基础，目标是能胜任实习里的脚本自动化、log 解析、测试数据处理和流程支持工作。

## 3. English 1-minute Introduction

> I built a beginner-oriented EDA and IC CAD automation training project. It is not intended to be production software, but it maps common internship tasks into five small modules. In Week 1, I used Shell scripts to check system dependencies and configure EDA-related environment variables. In Week 2, I implemented a Tcl log parser for DC/PT-style reports to extract area, power, cell count, worst slack and warnings. In Week 3, I used Python and pandas to analyze testchip measurement CSV data and generate yield and parametric reports. In Week 4, I used Makefile to simulate a reference flow including synthesis, placement, CTS, routing, STA and physical verification, with `.done` files for resume support. In Week 5, I wrapped the modules into a unified `chipcad` CLI. Through this project, I practiced Linux, Shell, Tcl, Python data analysis and basic EDA flow automation for CAD internship tasks.

### Week 4 Makefile Flow 自动化

## 5. 面试官可能问什么

### Q1：这个项目是不是你自己做的？

推荐回答：

> 这个项目是在 AI / Codex 辅助下完成的。我不是把 AI 输出直接当成结果，而是把岗位 JD 拆成模块，逐个运行、验证和整理文档。我重点学习了每个命令的输入输出、脚本结构和常见错误处理。对我来说，这个项目是一个系统训练过程，而不是简单复制代码。

### Q2：你 EDA 经验不足怎么办？

推荐回答：

> 我确实还不是有完整 tape-out 经验的工程师，但我申请的是实习岗位。我现在重点补的是 CAD 实习最常用的工程能力：Linux、Shell、Tcl、Python、log parsing、数据处理和 flow automation。我可以从维护脚本、整理 log、跑 flow、做报告这些任务开始贡献。

### Q3：为什么 EDA 里常用 Tcl？

推荐回答：

> 很多 EDA 工具内置 Tcl 解释器，比如 Synopsys 和 Cadence 工具。Tcl 适合做工具命令调用、约束设置、报告解析和流程脚本，所以 CAD 自动化岗位经常要求会 Tcl。

### Q4：`slack` 是什么？

推荐回答：

> slack 是时序裕量，可以粗略理解成路径到达时间和时序要求之间的差。正 slack 表示满足要求，负 slack 表示 timing violation。我的 Tcl parser 会提取 worst slack 和 violated path 数量。

### Q5：`.done` 文件为什么能断点续跑？

推荐回答：

> 每个 flow step 成功后创建一个 `.step_done` 文件。下次运行时 Makefile 先检查这个文件，如果存在就跳过该步骤。这样如果流程中间失败，修复后可以从失败点附近继续，而不用全部重跑。

### Q6：Python 分析里的 yield 怎么算？

推荐回答：

> yield = passed dies / total dies。项目里 CSV 的 `pass_flag` 是 1 表示通过，0 表示失败。脚本统计通过数量和总数量，得到整体良率，也按 wafer 分组计算 wafer-level yield。

### Q7：AI 在项目里起什么作用？

推荐回答：

> AI 主要用于辅助学习、生成初稿和整理 prompt，但脚本必须本地运行验证。我也把 AI prompt 生成封装到 chipcad 工具箱里，模拟团队内部把常见脚本需求标准化的做法。
